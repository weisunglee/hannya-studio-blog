下一款遊戲玩什麼、今天要走哪條路，可以直接請觀眾在聊天室投票。這次也補上訊息編輯的小工具，讓定時提醒、自動回覆和表情更容易設定。

### 觀眾打一則訊息就能投票

從「模組管理 → 聊天室投票」設定題目、2 到 6 個選項，以及每個選項對應的聊天室關鍵字。倒數可設為 1 到 180 分鐘，啟用並儲存後，OBS 會先顯示題目與選項；按「開始投票」才會開始計票。

例如把「聊天」的關鍵字設為 `1`、「玩遊戲」設為 `2`，觀眾傳送 `1` 或 `2` 就能選擇。比對的是整則訊息，會忽略頭尾空白和英文字母大小寫；在一段句子裡提到關鍵字，不會算成投票。

每位觀眾同一場只有一票。「允許改票」預設開啟，觀眾再傳另一個選項的關鍵字，就會把票改到新選項；關閉後則保留第一次選擇，重複傳送不會增加票數。

### 倒數結束後公布結果

OBS 會顯示倒數和目前票數。時間到或手動提前結束時，機器人會在聊天室公布結果；也可以在進行中延長時間。

「清除」和「結束」不同：進行中按清除會取消這場投票，不公布結果。系統只保留最新一場，開始新的投票會清掉上一場票數，操作前會先確認。

投票進行中仍能編輯下一場題目，儲存後的設定會留到下一場使用，不會改掉正在進行的選項。

### 定時發話也能使用模板運算

「自動發話 → 定時發話」現在和自訂指令共用模板能力，可以使用 `$(eval …)`、`$(let …)`、`choose()`，或以 `$(urlfetch https://…)` 取得外部 API 文字。編輯欄下方有進階運算式與 URL Fetch 說明連結。

想隨機換一句提醒內容，或讓定時訊息帶入 API 回傳的文字，就能在原本的定時發話設定裡完成。URL Fetch 使用固定的公開 HTTPS 網址，一則模板只能放一個，回傳內容須為純文字；取得失敗時會略過這次發話。它不能與 eval、let 混用。

定時發話沒有「這次是哪位觀眾輸入指令」的資料，所以 `{user}`、`{user_id}`、`{login}`、`{args}`、`{command}` 都會是空字串，也不會轉呼叫另一個指令。從自訂指令複製模板過來時，記得檢查這些欄位。

### 關鍵字回覆選自己的發話身份

「自動發話 → 關鍵字回覆」可以單獨選擇「發話身份」，讓這一類回覆使用指定的可用帳號；若該身份暫時無法使用，會改由系統機器人發話。

關鍵字回覆依然是整則訊息完全符合才回覆，區分大小寫並保留空白，和上面的投票比對規則不同。回覆內容限單行純文字，不支援指令或模板變數，也不能以 `!`、`/`、`.` 開頭。

自訂指令、定時發話與關鍵字回覆的訊息編輯器，也能選擇 Twitch 表情和 Emoji，並在編輯時預覽。表情仍要由實際發話帳號具備使用資格；可以先確認發話身份，再挑選適合的表情。
